# NewsDesk RSS Dashboard 1.0.5

CISA's feed could be refused by both existing download clients on a work PC
even while it opened in Edge. The reporter's native WinHTTP diagnostic returned
HTTP 200 and 30 articles on that same PC. This release adds the WinHTTP stack to
NewsDesk and makes it the first choice for automatic downloads.

## Changes

- **Automatic download order: WinHTTP -> Windows/.NET -> Python.** A successful
  client becomes the first choice for that site until NewsDesk restarts.
- Keep .NET as a fallback for Windows-authenticated proxy environments, and
  Python as a portable final fallback. Forced download settings still use only
  the selected method.
- Add **Windows (WinHTTP)** in Settings > Connection and show all three clients
  in connection diagnostics. Automatic remains the recommended setting.
- Use a streaming Windows client without additional packages or a browser
  process. Preserve download/decompression limits, total deadlines, conditional
  requests, HTTP(S)-only redirects, article destination checks and TLS checks.
  Automatic origin authentication and cookies remain disabled in WinHTTP.
- Preserve the HTTP status and latest CDN reference when all clients fail;
  ordinary HTTP errors, rate limits and resource-limit failures stop retries.

## Update

Close NewsDesk, download and extract `NewsDesk-1.0.5.zip`, then run
**Install NewsDesk**. Existing feeds, settings and reading history remain in
the separate user-data folder. Leave Connection set to **Automatic**, or select
**Windows (WinHTTP)** to test it directly.

The work-PC diagnostic is confirmed. Please verify adding/refreshing CISA and
a second refresh in the integrated application; issue
[#2](https://github.com/StevenMcGann/NewsDesk-RSS-Dashboard/issues/2) remains open
for that confirmation. An Akamai reference does not identify the exact rule
that refused the earlier clients.

See [the investigation and work-PC evidence](../CISA-FEED.md).

## Validation

The portable build verified its Python download hash and Python Software
Foundation executable signature. On bundled Python 3.14.8, 111 tests ran:
109 passed and two optional external-network tests were skipped.
Local regression tests exercise client ordering, per-site recovery,
proxy fallback, redirects, deadlines, response/decompression limits,
conditional requests, header injection and origin authentication behavior.
The packaged runtime fetched the live CISA feed through the default WinHTTP
path, stored 30 articles and refreshed again with no errors. Neither fallback
was called in that check. ZIP CRC checks passed and packaged source bytes
matched the reviewed files. CI results and the archive checksum accompany the
published release.

If this update regresses another feed, select another download method in
Settings > Connection while reporting the error. The preceding 1.0.4 release remains available as a
rollback package; the 1.0.5 change requires no database migration.
